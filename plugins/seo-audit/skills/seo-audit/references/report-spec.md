# Report specification

This is the report for people. The second output, the hands-off brief for agents, is in `handoff-spec.md`; both come from the same `audit.json`.

The report is one self-contained HTML page. `assets/report-template.html` implements everything below and renders it from one `<script type="application/json" id="audit">` block; you write only that JSON (`audit.schema.json`, examples in `assets/example-audit.json` (Ukrainian) and `assets/example-audit.en.json` (English)). Rebuild from this spec only if the template cannot be used.

## Look

Annual-report style: white ground, black ink, one vermilion accent (#ff4a1c) only for the biggest leak and the top 3 bets, amber for warnings; dark theme on #120d0b (the page follows `prefers-color-scheme` and a `data-theme` attribute on the root). Titles in Sofia Sans Condensed 800, text in Sofia Sans (both cover Latin and Cyrillic). Simple stroke SVG icons per lens, no emoji. It must work at 360px: tables become stacked cards, the search path turns vertical. Every derived number (ICE, health index, quick wins, confidence, leak rates) is computed by the template, never typed.

Headings state their point ("The Russian home page redirects to the Ukrainian one"), not a topic ("Technical SEO"). If any data is sample or assumed, say so once in the small label at the top. Footer: generated by seo-audit.

## Sections, in order

1. **Header** - headline = the biggest leak, with its number; one-sentence lead; KPI row (up to 4): SEO health index (`{health}`, average of lens scores), the leak metric vs target, one more key number (indexed pages, non-brand click share), quick wins (`{qw}`). Then **leaks vs target**: one row per leak, `v` of base `b` as a rate against a suggested target `t` % (CTR by position band, indexed vs submitted, non-brand share of clicks, organic sessions with a key event). `v: null` = hatched "no data" row. Under it, the search maturity strip (Crawlable, Indexed, Ranking, Clicked, Converting; the current one filled) with one sentence on what blocks the next stage.
2. **Lenses** - radar of the 11 lens scores (0-100, low = leak or untapped potential) beside a grouped list with meters (4 groups: access for search, match the query, chosen in results, authority and demand).
3. **Technical checklist** - `checks`: one row per check with a status mark (ok / warn / bad / no data), a short value on the right and a one-line note. Cover what you checked: status codes, redirects of old URLs, canonicals, hreflang, sitemap, robots.txt, AI crawlers, Core Web Vitals (field or lab, say which), structured data, analytics tag and key events, bot protection. Unchecked items are `nd`, not omitted, when they matter.
4. **Search path** - a route of 6-8 stops from Googlebot to a lead: crawl -> index -> rank -> snippet -> click -> landing -> conversion (adapt), with the owner of each (Googlebot, developer, content, analytics), one-line pain and status ok / leaks / blocks.
5. **Impact-effort matrix** - numbered dots per opportunity; filled = optimize, outlined vermilion = explore; quick-wins quadrant tinted; heading states how many quick wins.
6. **Opportunities table** - sorted by ICE, filter chips (all / optimize / explore), columns: #, opportunity (observed/hypothesis badge), lens (icon + name), type, I, C, E, ICE with bar; top 3 highlighted.
7. **Next 3 actions** - cards with hypothesis ("If we X, then Y improves, because Z"), success metric, cheapest test.
8. **Full plan for every opportunity** - one collapsible row per opportunity, top 3 open, "expand all" button. Body: **Why it is here** (GSC rows, URLs, status codes, owner's words), **What to do** (3-5 numbered steps naming the real tools: the site's SEO plugin, redirect rules, GSC reports), **Metric**, **Effort**, **Risk / guardrail**. Top 3 also: alternatives considered, experiment (risk type, success threshold), pre-mortem, and 2 title/description variants when the change is about a snippet.
9. **Data and confidence** - sources with statuses, confidence meter (ok = 1, demo = 0.6, no = 0, averaged), the start questions with answers, a collapsible glossary, a collapsible "how this report was made".

## Data shapes and language

The full shape is in `audit.schema.json`; `scripts/validate_audit.py` checks it plus the skill's rules. The parts that are easy to get wrong:

- `lang` (`uk` or `en`) picks the interface labels from the template's `UI` dictionary. For another language, add an entry with the same keys.
- `text`: `label`, `headline`, `lead`, `funnelNote` (under the leaks: period, source, "targets are suggested benchmarks"), a heading `…H` and intro `…P` per section (`lenses`, `checks`, `journey`, `matrix`, `ops`, `next`, `plan`, `data`), `how` (list), `footer`. Tokens `{health}`, `{qw}`, `{n}`, `{conf}` are filled in; `[[words]]` turn red. All text is escaped. A missing or empty key removes that element.
- `kpis`: up to 4 `{v, l, hot?, src?}`. A literal number needs `src` = the name of an entry in `sources` that is not `no`.
- `leaks`: `[{l, v, b, t, sub?, src}]`. The row label shows "v / b"; the big number is v/b in %; the bar fills toward the target. Numbers need `src`.
- `funnel` is still supported (`[{l, n, hot?, note?, sub?}]`, first item is the base) for a step funnel such as impressions -> clicks -> engaged sessions -> leads. Use one of `leaks` or `funnel`, not both.
- `stage`: `{cur, note}`; `cur` 0 Crawlable … 4 Converting.
- `checks`: `[{t, st: "ok"|"warn"|"bad"|"nd", v?, note?, src?}]`. A `v` with a number needs `src`; `nd` has no `v`.
- `lenses`: 11 items `{k, n?, i, g, s}`; `i` and `g` from `lenses.md`.
- `ops`: `{t, l, ln, x: "opt"|"ex", ev: "obs"|"hyp", I, C, E}`; ids are 1-based positions. `detail` and `plans` are keyed by that id as a string.
- `answers`: `{q, a, skipped?}`; a skipped one states the assumption in `a`.
- `sources`: `{name, note, status}`.
- `glossary`: `{term: {g, d}}`. Include every abbreviation you use: CTR, GSC, GA4, hreflang, canonical, 301, 404, 429, LCP, INP, CLS, CrUX, ICE, x-default, JSON-LD, SERP, cannibalization...

## Tooltips for terms

Every abbreviation, metric and term in the report is a dotted-underlined button with a tooltip: the term, a 2-4 word gloss, and one or two plain sentences, ideally with this site's own number ("12 clicks of 18,425 impressions = 0.07%").

- Desktop (hover-capable fine pointer): opens on hover.
- Phones and tablets: opens on tap; a second tap or a tap elsewhere closes it.
- Keyboard focus opens it, Escape closes it; scrolling more than 40px closes it.
- Definitions live in one glossary object; the script wraps the first occurrence of each term per paragraph, cell or checklist row.

## Mobile table cells

In the stacked (phone) table each cell's content is wrapped in one `<span class="cv">`, after terms are wrapped and after every filter re-render. On phones the I, C, E columns are hidden and shown inside the ICE cell ("576 = 8x8x9").

## Robustness

- Charts are drawn at real pixel size with a ResizeObserver; bars and meters are HTML rows with a % width.
- All script sits in one block at the end of `<body>`, wrapped in `{ }`; check it with `node --check` if you edit it.
- `localStorage` is not used.
