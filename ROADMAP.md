## Done

### Two outputs: a report for people and a hands-off brief for AI agents (1.1.0)

Shipped in 1.1.0: `scripts/build_handoff.py`, `references/handoff-spec.md`. The plan below is kept for reference.

Today the skill delivers one designed HTML report. Add a second output from the same `audit.json`, so the requester can hand the audit straight to an AI agent (Claude Code, Cursor, a CMS agent) for implementation.

1. **Report for people** - as now: annual-report design, charts, icons, tooltips, light and dark themes.
2. **Hands-off brief for agents** (`audit.handoff.md`) - plain Markdown, no design, no icons, no charts; structured for execution, not for reading.

Draft shape of the brief:

- **Context**: site, CMS and SEO plugin, languages and URL patterns, audit date, data period, sources with their status.
- **Constraints**: read-only data was used; what the agent must not do (no doorway pages, no bought links, no fake schema, no mass noindex without review, back up before bulk changes).
- **Tasks**, sorted by ICE, one block per opportunity with stable ids (`SEO-01`...):
  - goal and the evidence it rests on (GSC rows, URLs, status codes), with `observed` / `hypothesis`;
  - exact targets: URL lists, current vs expected values (status code, canonical, hreflang set, title/description text);
  - steps as an ordered checklist;
  - **acceptance criteria** an agent can verify (e.g. "`curl -I /ru/` returns 200", "hreflang on `/` lists uk, ru, en, x-default, all 200", "URL Inspection shows indexed");
  - dependencies between tasks, owner type (developer / content / analytics), effort, risk and rollback;
  - what needs a human decision before the agent acts.
- **Measurement**: metrics, baselines and the re-check date.
- **Open gaps**: checks marked "no data" and which source would close them.

Implementation notes:

- Generated by `scripts/build_handoff.py` from the same `audit.json`, so both outputs never disagree; `validate_audit.py` keeps guarding the data.
- Possibly a few new optional fields in the schema for machine-checkable targets (`targets`, `accept`, `depends`), ignored by the HTML template.
- Optionally a JSON variant (`audit.handoff.json`) for agents and task trackers that prefer structured input.
- The skill asks at the end (or in the start questions) which outputs are wanted; default: both.
- Still open: the same idea for [product-lens-audit](https://github.com/artemhorbenko/product-lens-audit).
